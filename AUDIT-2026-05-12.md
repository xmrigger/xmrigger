## 2. Findings — federation layer must close these

The PrevhashMonitor receives `(peerId, prevhash, ts)` from a federation it
trusts. Today nothing in the codebase verifies those three arguments. Anything
that calls `onPeerAnnounce` *is* the trust boundary. v1.0 federation closes
these.

### F1 — `peerId` is an unverified string
`onPeerAnnounce(peerId, prevhash, ts)` accepts any string as identity
(`prevhash-monitor.js:164`). This is the literal "Sybil ≥50%" hole the inline
comment at line 41-44 names.
**Federation layer MUST**: derive peerId from an Ed25519 pubkey proved at
HELLO, and gate `onPeerAnnounce` behind that proof (mining-bound attestation
via signed-recent-prevhash).

### F2 — `ts` from caller is not bound to a signed payload
Default ts is `clock.now()` (line 166). Even when passed in, nothing ties it
to a cryptographic attestation by the peer. A federation that took ts off the
wire without verification would allow timestamp-injection: a peer can claim
to have observed prevhash X "30 seconds ago" arbitrarily.
**Federation layer MUST**: extract ts from inside the signed frame, refuse
frames with ts outside a sanity window (`|now - ts| > ~5 min`).

### F3 — Peer map has no explicit size cap
Eviction is purely time-based (PEER_STALE_MS = 120 s). A burst of rotating
identities can fill the map for two minutes regardless of memory pressure.
Today not exploitable because nothing creates fluid identities; with the new
federation if we're not careful it becomes a vector.
**Federation layer MUST**: enforce a max peer count (suggest 1000), LRU
eviction beyond that, **before** calling `onPeerAnnounce`.

### F4 — No rate limit on `onPeerAnnounce`
A peer can call it 10 000 times/s. Each call triggers `_tally()`, O(n) over
the peer map. Live CPU saturation vector even without identity churn.
**Federation layer MUST**: token-bucket per peer (suggest 5 frame/s
sustained, 20 burst). Excess frames dropped + strike (existing `limits.js`
pattern).

### F5 — `_tally()` is O(n) per poll and per `onPeerAnnounce`
Acceptable for n ≤ 1000. Scales poorly at 10k+. Out of scope for v1.0 with
hard peer cap 1000. Document as known.

### F6 — `prevhash` format is unvalidated
`if (!prevhash) return` (line 165) is the only check. Caller may pass a 1 MB
string. PrevhashMonitor stores it, broadcasts it, peer-loop iterates it.
**Federation layer MUST**: reject any prevhash not matching `^[0-9a-fA-F]{64}$`
at frame parse. Stricter: bind it to the wire format (fixed 32 bytes), so by
the time `onPeerAnnounce` is reachable the prevhash is already validated by
construction.

### F7 — `HashrateMonitor` is not deterministically testable
Unlike PrevhashMonitor, it uses `Date.now()` and `setInterval` directly
(no clock injection). Test suite uses real timers + monkey-patched
`_fetchNetworkHashrate` — works but is non-deterministic at the timer level.
**Recommendation (separate refactor, not blocker for federation v1.0)**:
mirror PrevhashMonitor's clock injection pattern. Mark as follow-up task.

### F8 — `forkDetected` from pool-self-reported triggers immediate evacuate
`hashrate-monitor.js:159` accepts `forkDetected: true` from
`/pool/health` and evacuates without grace. A malicious pool can force its
own miners to evacuate (effectively self-censorship of its own pool).
Not a miner-security issue (miners benefit) but asymmetric: pool can use it
as a soft-DoS on its own user base.
**Documentation only**: behaviour is intentional and benign for miners.

### F9 — Evacuate cooldown vs slow in-flight polls
After evacuate, `_evaluate` drops results for `gracePeriodMs` (60 s default).
A poll started right before evacuate that resolves after 60 s would slip
through. In practice fetch timeouts are 6-8 s so this is theoretical.
**Documentation only**.

### F10 — DNS rebinding not blocked
`_isPrivateOrLoopbackHost` only inspects the hostname string. A public
hostname that resolves to 127.0.0.1 (DNS rebinding) is not blocked. Endpoints
in `DEFAULT_NETWORK_URLS` are reputable hosts so the risk is low, but a
compromised endpoint configured by the operator could exfiltrate to localhost
via this path.
**Mitigation (separate hardening, optional v1.x)**: resolve hostname to IP,
re-check against private-range list before connect. Adds DNS round-trip cost.
Track as known limitation in SECURITY.md.

### F11 — `Promise.any` on network hashrate has no aggregate timeout
Each endpoint times out at 6 s. Aggregate is at most 6 s (first-resolves).
Acceptable. Document.

### F12 — `parseInt` is lenient
`_extractDifficulty` falls back to `parseInt(v, 10)` (line 280). `parseInt`
accepts `"123abc"` → 123. If an endpoint returns a partly-numeric string we
silently accept it. Not exploitable today but encodes a non-strict trust in
data shape. **Minor**: tighten to `Number.isInteger(Number(v))` check.

### F13 — No ban list anywhere
PrevhashMonitor cannot ban a peer; HashrateMonitor cannot ban a federation
hint source. If a peer floods or equivocates today, the only defense is
"shut down the proxy and restart".
**Federation layer MUST**: maintain a local ban list (in-memory plus optional
persistent file) keyed on IP of the misbehaving session. Bans short
(1 h default) to absorb misconfiguration without permanent damage.

### F14 — No TLS pinning on network endpoints
Default Node CA store. A compromised CA could let a MITM serve fake
difficulty data. Mitigated by plurality (5 endpoints, first to respond
wins, but no cross-check). Document.

### F15 — `_fetchPoolHealth` JSON shape loosely typed
`if (typeof data.hashratePct === 'number')` is the only check
(`hashrate-monitor.js:225`). Other fields (`forkDetected`,
`gracePeriodEndsAt`) are not validated before use at line 159.
A malformed `forkDetected: "true"` (string) would be truthy and trigger
evacuate. **Minor**: add `=== true` strict check.

## 3. Federation contract — what v1.0 must implement

API the PrevhashMonitor already expects (preserve byte-for-byte):

```js
federation.broadcastPrevhash(prevhash)
federation.on('prevhash-announce', ({ from, prevhash, ts }) => ...)
```

Contract that v1.0 MUST guarantee at this boundary:

| Field | Guarantee at delivery |
|---|---|
| `from` | Verified Ed25519 pubkey of the remote session (hex, 64 chars). NOT operator-supplied string. |
| `prevhash` | Hex `^[0-9a-fA-F]{64}$`, parsed from a fixed 32-byte wire slot. |
| `ts` | Number, extracted from the signed payload AAD, within `±5 min` of local clock. |

Frames that fail any of these MUST be dropped silently before reaching
`onPeerAnnounce`. Optional: emit `federation.on('peer-banned', ...)` for
operator observability.

Equivocation hook (NEW capability the federation introduces): if `from` posts
two distinct `prevhash` values for what looks like the same block (height
inferred or signaled), the federation MUST locally ban the IP of that
session for 1 h and emit `peer-banned`. PrevhashMonitor remains
height-agnostic; the equivocation cache lives in the federation module.

## 4. SPEC v0.1 vs SPEC v1.0 federation — what gets deprecated

SPEC.md v0.1 §"Federation Alert Protocol" defines an **optional JSON wire
format**:

```json
{ "type": "guard-alert", "reason": "...", "hashratePct": 0.32,
  "origin": "proxy.xmr", "ts": ... }

{ "type": "prevhash-announce", "prevhash": "0xBBBB", ... }
```

This is:
- string-typed (`type`, `reason`, `origin`)
- variable-length (`origin` could be anything)
- unsigned (`origin` is a free string, no Ed25519 attestation)
- subject to JSON parser quirks (`JSON.parse` of untrusted input,
  prototype-pollution surface)
- no replay protection, no anti-equivocation

v1.0 federation REPLACES this entirely with a binary fixed-size signed wire
format (3 frame types, 192 B each, ChaCha20-Poly1305 AEAD, Ed25519 signed
inside AEAD, ephemeral identity per session, mining-bound HELLO). The v0.1
JSON format is **deprecated** in the v1.0 SPEC. Code that implements only
v0.1 JSON does not interoperate with v1.0.

Migration note for SPEC.md: bump §Federation Alert Protocol to "v0.1 legacy,
deprecated; see SPEC-FEDERATION-v1.md".
